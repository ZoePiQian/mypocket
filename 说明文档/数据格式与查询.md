# 数据格式与查询

## 记账模板与凭证

`常用模板.md` 使用 `finance_schema: 1`、`finance_kind: templates`，在专属标记之间保存十列模板表（名称、范围、专项 ID、类型、分类、账户、可选原币金额、币种、备注、模板 ID）。它不参与收支统计。模板仅保存可复用字段，不保存账目日期、交易 ID、汇率或凭证；删除模板不会改变既有流水。

月流水与专项流水继续兼容原七列人民币表和十三列多币种表。首次添加凭证时，在表格末尾追加「凭证」列，成为八列或十四列；已有行补空值，表格外正文保留。凭证列为 `[[库内文件路径]]`，多份用 `<br>` 分隔；不要手改成外部网址或别名链接。

凭证原文件保存到数据目录的 `凭证/YYYY/MM/`，路径参与记录冲突检查。日期编辑、跨月迁移、日常与专项互移、回收站及恢复均保留关联。移除关联和回收记录均不删除文件。原文件名会经过清理并追加唯一后缀，避免覆盖同名文件；界面显示简短名称。

支持 PNG、JPG/JPEG、WebP、GIF、PDF，每笔最多 10 份，每份 10 MB。导入会核对扩展名及文件头，只在保存账目时执行。保存失败、取消或数据目录切换时，已经写入的凭证文件会保留，供用户核对；结束导入登记不会扫描全库笔记，也不会删除文件。

同步时应包含 `常用模板.md`、凭证文件夹及原文件。仅同步 Markdown 会保留金额与链接，但另一设备暂时无法查看未同步的图片或 PDF。

本文说明 MyPocket 1.0.1 的 Markdown 数据结构。`finance_schema` 表示文件格式，不是插件版本。以下数据均为虚构格式示例；操作教程见[图文使用指南](../INTRODUCTION.md)，也可从插件内的「使用指南」离线阅读。

## 多币种

原人民币流水表继续兼容，不在启动时改写。首次保存带汇率的记录时，七列流水后追加：`原币金额、币种、汇率日期、1元兑美元、1元兑日元、汇率来源`。原来的 `金额（元）` 为按该笔汇率换算后的人民币金额；原币金额保留最多两位小数。`currency: CNY` 月笔记属性指人民币换算列，并不表示每笔原币均为人民币。

汇率以人民币为基准，`rates.USD` 表示 1 CNY 可兑换多少 USD，`rates.JPY` 同理。例如每元兑 0.125 美元、20 日元时，10.01 USD 折合 80.08 CNY 或 1601.60 JPY。换算约到两位小数后统计；UI 按绝对值向上取整显示，笔记保留实际精度。插件校验人民币金额与原币金额、汇率的一致性，手动改动其中一项后请同步修正其他项，或使用面板编辑。

来源为 `Frankfurter / ECB` 或 `手动`，日期是实际参考汇率日期，周末等日期可能取前一个可用日期。同一笔已保存的汇率不随联网更新改变。旧人民币账目切换外币汇总时按记录日期查询并使用本地缓存，原笔记保留。

参考汇率缓存与账目快照分开。当日查询若只取得前一可用日的汇率，随后会重新核验，避免把临时结果永久当成当日汇率。历史日期在七天观察期内至多每天重新查询一次，取得对应日汇率后稳定缓存；周末、假期仍使用服务提供的可用参考日，观察期后再次查得的结果可稳定保存。离线时可使用已有缓存，已保存交易的汇率快照不被替换。

缺少换算所需汇率时，相关合计显示「待补全」，不会用 0 或一个不完整的数值冒充总额；已知部分仅作为明确标注的参考。只有开启多币种后才展示相关记账字段。此类显示状态不改变 Markdown 金额。

固定支出扩展为九列，追加 `币种`，每次金额为原币价格。理财笔记 `currency` 可为 CNY、USD、JPY；原币本金及估值分别保存在 `principal`、`current_value`。汇率快照保存在 `fx`、`valuation_fx` YAML 属性，格式为：

```yaml
fx:
  date: "2026-10-08"
  source: "Frankfurter / ECB"
  rates:
    CNY: 1
    USD: 0.125
    JPY: 20
```

以上数值仅为格式示例。默认记账币种、汇总币种、参考汇率缓存属于插件设置；账目金额和已保存的账目汇率仍在 Markdown 中。查询 `amount` 等字段时，注意多币种原币金额不能直接相加。

## 统计范围

日常流水、日常分类图、每日消费和月报仅统计日常记录。专项在 `专项/` 下独立保存，绝不混入月度流水表。插件版本为 1.0.1；专项使用的 `finance_schema: 3` 仅表示笔记格式，不随插件补丁版本改变。

记录列表默认仅展示最近 10 条，同一日期、同一笔记内按表格中较后的记录优先显示。金额汇总使用全部匹配记录，不受列表折叠影响。未来日期到当天才计入实际统计；净支出扣除退款，类型筛选中的支出合计为退款前金额。

「跨月查账」直接读取已有日常与专项记录，不增加新的笔记格式或汇总文件。时间条件包含起止日；最近 3 / 6 个月分别从本月之前 2 / 5 个月的第一天起算，实际统计截止到今天。支持 1900–9999 年内的自定义日期，跨年份使用相同规则。

查询范围分为日常、全部专项、单个专项，不混合日常与专项；归档专项的历史交易可查。类型、分类、关键词和日期共同决定匹配集合，合计使用全部匹配行。支出与退款分别累计，「全部类型」下以支出减退款计算净支出，收入单独列出；只选支出时只展示退款前金额。查询状态保存在视图中，个人原始记录仍保留在各自的 Markdown 文件里。

## 专项账本

路径为 `流水数据/专项/名称.md`，每个专项一篇，可跨年追加。名称不能重复（含已归档专项），比较时忽略首尾空格、英文字母大小写及全半角等价差异。修改名称时同步重命名文件，通过 Obsidian 按库设置处理链接。内部 `id` 保持不变，固定支出与交易关联不依赖文件名。

旧版自动生成的 `名称-专项ID前8位.md` 在扫描时通过 `FileManager.renameFile` 整理，不复制或重写正文。发现重名、重复 ID、目标路径被占用或格式问题时保留文件并提示；手动选择的其他路径不会自动改名。

```yaml
---
finance_schema: 3
finance_kind: project
id: "独立且唯一的专项ID"
name: "装修"
status: active
start_date: null
budget: "100000.00"
currency: CNY
budget_date: "2026-11-01"
budget_fx: null
categories: [材料, 人工, 家具]
description: "专项说明"
cover_icon: home
cover_color: sand
tags: [财务, 专项]
---
```

其中 `status` 为 `active` 或 `archived`；预算、开始日期、说明可留空。预算和预算币种仅用于参考，不产生流水；`budget_fx` 保存预算日期的汇率快照，格式与普通 `fx` 相同。

`cover_icon` 与 `cover_color` 保存专项封面外观，不参与金额计算。图标值为 `folder`、`home`、`compass`、`dumbbell`、`book`、`heart`、`car`、`briefcase`、`ball`、`paw`；配色值为 `sage`、`mist`、`sand`、`rose`、`slate`。旧笔记缺少字段或外观值无法识别时，使用通用图标与松绿配色，读取时不补写文件，账目继续正常统计。保存外观后会将所选值写入属性。

明细沿用下文的七列 / 十三列交易表及 `transactions:start/end` 定位标记，只允许「支出」「退款」，日期不受月份限制。每行的所属专项由所在笔记的 `id` 决定，记录 ID 在所有日常与专项记录中须唯一。专项类别独立存储在本篇属性中，不污染日常常用分类。表格外的自由正文、图片和双链由用户维护，插件保留。

迁移保留原行的记录 ID 与财务字段，同一记录只出现在一个有效账本中；跨文件移动先校验快照，写入出错时尝试回退。同步修改使回退无法完成时保留相关文件、显示重复 ID 提示，重复记录暂不计入统计，等待用户核对。可在「个性化设置 → 数据恢复 → 重复记录」比较支持处理的流水版本后选择保留哪一份。

专项删除行保存到 `回收站/专项/专项ID.md`，不参与统计。该回收站可能保留同一记录 ID 的不同历史版本；「数据恢复」会分别展示，确认后只恢复所选版本。记录回到原专项，保留 ID、金额、原币、汇率和备注；原专项已归档时需要先重新启用。已有有效记录使用相同 ID 时停止恢复，避免重复记账。

## 日常月度流水表

文件路径：`流水数据/流水/YYYY/YYYY-MM.md`，例如 `流水数据/流水/2027/2027-01.md`。同月的全部支出、收入、退款在同一张普通 Markdown 表中，金融金额不另存为 JSON。年份取自记录日期，按需创建目录。

```yaml
---
finance_schema: 2
finance_kind: monthly
month: "2026-10"
currency: CNY
tags: [财务, 流水]
---
```

```markdown
<!-- local-finance-notes:transactions:start -->
| 日期 | 类型 | 分类 | 账户 | 金额（元） | 备注 | ID |
| --- | --- | --- | --- | ---: | --- | --- |
| 2026-10-07 | 支出 | 外卖 | 微信 | 32.50 | 晚饭 | 638c9fe7-228a-4c84-a8b5-111111111111 |
| 2026-10-07 | 收入 | 工资 | 银行卡 | 8500.00 | 十月工资 | 638c9fe7-228a-4c84-a8b5-222222222222 |
<!-- local-finance-notes:transactions:end -->

## 本月的笔记与凭证

今天加班，晚饭关联 [[工作项目]]。
![[晚饭收据.jpg]]
```

表格仅在两个标记之间读取；标题、标记和七列结构请保留。类型为「支出」「收入」「退款」，金额都填正数，最多两位小数。插件用整数分计算；笔记保留实际精度，面板按绝对值向上取整显示。

日期须属于 month 对应的月份。通过面板跨月改日期会移动该行；自由正文继续留在原月。账户、备注可为空，日期、类型、分类、金额、ID 必填。ID 须唯一，复制为新记录时需要新 ID。

表单自动处理表格转义：竖线为 `&#124;`、反斜杠为 `&#92;`、换行为 `<br>`，HTML 字符采用实体。手工编辑可以沿用这些写法，避免把备注拆成多列。表格外的正文可以自由使用 Markdown 和双链。

普通金额、分类和备注可直接编辑，面板重新读取。格式错误的行会展示行号；有效行继续参与统计，写操作会暂停直到格式修正。面板编辑仅更新目标行，不重写其他记录、月笔记属性和正文。

同一行在打开表单后被其他编辑器修改，会拒绝覆盖并要求重新打开。其他行的改动可以保留。流水表被同步软件同时改写仍可能产生合并冲突，应通过文件备份核对原始记录。

切换数据目录不会迁移笔记。打开表单、恢复预览或跨账本移动后再切换目录，原操作会拒绝保存；请在目标目录中重新打开。移入日常前还会校验目标月笔记的 `month` 属性，目标月份错误时不会移走源记录。

## 月报与年份目录

月报保存为 `流水数据/月报/YYYY/YYYY-MM.md`，例如 `流水数据/月报/2027/2027-01.md`，在点击「生成 / 更新月报」时创建。再次生成仅更新自动汇总区域，保留手写复盘。

流水与月报的年份目录按需创建，文件名保留完整的 `YYYY-MM`。跨年修改记录日期时，目标行移入相应年份、月份的流水笔记，原月的自由正文保留。固定支出的实际付款也按付款日期保存到对应月。

旧的平铺月笔记会自动移入年份目录，并使用 Obsidian 的文件管理接口更新相关链接。月份属性或表格有误、新旧路径同时存在、目标被占用时会提示检查，不覆盖任何一份笔记。整理目录不修改金额、记录 ID 或笔记的属性格式。

## 兼容导入

遇到 `finance_schema: 1` 且类型为 expense、income、refund 的单笔笔记时，插件会自动合并到月度流水。完整原文件改名为 `旧版备份/<原相对路径>.md.bak`，保留额外属性；正文另外复制到月笔记，后续重复刷新不会再导入同一笔。

损坏笔记、重复 ID 或不支持的币种保留原文件并显示提示。迁移先写入并核对月表，再归档原件；中断后可重试，不重复追加金额。备份不参与统计。

## 回收站与重复记录

删除日常流水只移走该行，进入 `回收站/YYYY.md` 的全年共用表，不删除月笔记正文；专项流水进入 `回收站/专项/专项ID.md`。两类回收站都不参与统计。

通过「个性化设置 → 数据恢复」或面板底部的「数据恢复」进入：

- **回收站**：核对日期、实际金额、备注和恢复位置，点击「预览恢复」，再确认。日常记录恢复到日期对应的年 / 月流水，专项记录恢复到原专项。若同 ID 有多个历史版本，仅恢复所选版本并移除对应回收行。
- **重复记录**：按交易 ID 列出冲突版本。确认属于同一笔交易后，选择「保留此版本…」，其余支持处理的流水版本移至对应回收站。金额和备注不会自动合并，也不按相同金额或名称判重。若实际是不同交易，应先为它们设置不同 ID。

确认时重新校验整个预览涉及的文件、记录位置及数据目录；预览后发生外部修改会停止操作，需刷新后再核对。跨文件处理采用先写目标、再移除来源的流程，失败时尝试回退并保留并发修改。操作成功后刷新统计，并尝试更新受影响月份已有的月报；若月报更新失败，记录操作不需重做，可单独重新生成月报。

此工具处理月流水和专项中的交易行。整篇删除的理财笔记应从 Obsidian 本地回收站恢复；旧单笔格式、重复专项元数据 ID 或无法解析的笔记会提示人工检查，不会自动删除或改写。

## 理财笔记

理财按产品保留一篇持续更新的笔记，使用原有属性格式：

```yaml
---
finance_schema: 1
finance_kind: investment
id: 638c9fe7-228a-4c84-a8b5-333333333333
date: "2026-10-07"
name: 示例基金
principal: 10000
current_value: 10300
valuation_date: "2026-10-07"
currency: CNY
category: 基金
account: 支付宝
status: active
due_date: null
memo: 长期持有
tags: [财务, 理财]
---
```

principal 是剩余在投本金，须大于 0。current_value 是手填的当前估值，可以为 0，未填设 null；填写估值时需真实 valuation_date。未来估值暂不计入盈亏。status 为 active 或 closed；已结束和未来开始的产品退出在投合计。due_date 可空，仅展示日期。

浮动盈亏 = 已填写且生效的估值 − 对应持仓本金。理财采用 Obsidian 的属性更新接口，保留其他自定义属性和正文。

## 查询与存储约定

月流水是表格行，Dataview 普通属性查询不能逐笔读取。直接打开月笔记或生成月报即可查看明细和同口径统计，无需安装额外插件。自己的脚本可以依据固定表头、标记和 ID 解析本地文件。

月笔记、理财属性、月报都使用 Obsidian 公共 Vault / FileManager API。插件仅扫描配置的数据目录，排除备忘录、旧版备份和回收站；目录之外的笔记不参与统计。设置保存常用选项、偏好和参考汇率缓存，不保存账目金额。

面板读取复用按文件记录的内存解析缓存；保存、文件变化和目录切换使相关缓存失效，手动刷新与生成月报会读取最新内容。缓存仅用于减少重复读取，不产生另一份账本或本地数据库。写入、迁移与恢复仍以最新文件内容校验，刷新时保留当前筛选与浏览位置。

## 备忘录

文件路径为当前账本目录下的 `备忘录.md`，内容为原样保存的自由文本或 Markdown，不要求财务属性，也不参与账目解析或兼容导入。所有备忘共用此文件，和月流水分开。

弹窗停止输入后自动保存，关闭前也会保存。写入前比较打开时的文本快照，遇到外部修改、文件改名、路径替换或账本目录变化时停止覆盖并保留草稿。

```markdown
## 续费与使用笔记

记录续费理由、套餐变化和凭证。
```

付费周期为「按年」或「按月」，状态为「启用」或「停用」。首次付款日在所属年份内，金额正数、最多两位小数，备注最多 1500 字。ID 使用不超过 64 字的字母、数字、短横线或下划线，通常由插件生成 UUID。列宽可由编辑器自动对齐，表头、标记和八列结构须保留。

此表保存计划，不直接加入月度支出。确认付款后，实际金额写入所选归属：日常月流水或一个专项，分类为「固定支出」，付款 ID 为 `lfn-fixed-<清单项目ID>-<对应期次日期>`。这个 ID 在日常与专项之间统一查重，用于关联清单与付款、防止同一期重复记账，请保留。

旧八列表继续兼容；带币种的九列表追加 `币种`，指定专项归属时再追加第十列 `所属专项ID`。该列留空代表日常，填写专项内部 ID 代表该专项；关联不依赖专项名称。更改计划归属只影响后续付款，不移动已付款记录。专项内打开清单默认筛选该专项，新建计划也默认使用该归属；切换「全部固定支出」可查看完整清单并沿用上一年的计划。

月付从首次付款日所在月份至十二月；沿用上年清单时，月付改为新年一月、保留原日期中的日，年付则顺延一年。短月按月底处理，例如一月 31 日、二月 28 日、三月 31 日；闰年二月为 29 日。沿用清单会生成新项目 ID，不复制旧付款。

本年计划费用是启用项目各期的参考费用合计。月均参考为本年计划除以 12 并约到分，不生成摊销流水。实际固定支出是付款流水按实际日期与实际金额计算，退款抵扣。价格调整不会改写已付款的原始金额；停用不删除历史流水。

管理页的计划、实际付款与月均参考随所选归属同步计算；日常面板只含归属日常的清单与实际付款，专项付款不影响日常月账单。固定清单用于支出计划，不提供自动生成「固定收入」的功能；收入应在到账后按实际金额单独记录。

若付款已在普通流水中手工记过，请避免再对同一笔「记录付款」。重复检查识别插件创建的关联 ID，不能自动判断两条不同 ID 的手工账目是否是同一笔。实际付款必须属于所选年份，不允许未来实际付款日期。

固定支出笔记支持直接编辑，插件只修改选中的项目行并保留正文。已有付款的周期和首次日期请通过新增替代项目处理，避免切断期次关联。格式错误、重复项目 ID、过期编辑表单会提示并停止付款保存。
