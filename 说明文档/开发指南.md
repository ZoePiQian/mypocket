# 开发与维护

MyPocket 正式版为 **1.0.0**，作者为 **Zoe Qian**。这一版包含桌面界面和手机适配，两端共用源码、安装包和本地 Markdown 账本。

插件内部 ID 与安装文件夹继续使用 `local-finance-notes`，以保留已有设置、命令和账本关联。插件版本与笔记的 `finance_schema` 是两套独立编号；发布新版本不要修改现有账目格式标识。

GitHub 源码仓库的根目录对应下文的「应用安装包」；「财务管理 / 流水数据」是用户本地仓库的数据目录，不随源码或安装包发布。公开仓库自身的 `.gitignore` 也排除了个人设置、流水、备份和临时文件。

## 目录用途

Obsidian 侧边栏中，「财务管理/流水数据」保存个人数据，「财务管理/应用安装包」保存应用文件。下表中的路径及后续命令均以 **应用安装包** 为工作目录。

「财务管理」顶层只显示这两个目录。维护、构建与打包都在「应用安装包」内进行，不在顶层另建 `账本`、`docs`、`release`、`scripts`、`src` 或另一份 README。根目录隐藏的 `.gitignore` 用于阻止个人流水和设置被提交到代码仓库，应保留。

## 构建与检查

使用 Node.js 18 或以上版本，构建与检查无需下载依赖。命令在「应用安装包」目录执行：

```text
npm test
npm run build
npm run check
```

`npm test` 执行逻辑回归：最近 10 条排序、精确金额、日常 / 专项隔离、固定计划与实际付款、跨日参考汇率缓存、目录切换保护、增量读取、回收恢复和重复 ID 处理。`check-attachments.cjs`、`check-templates.cjs`、`check-history.cjs` 同时注册凭证生命周期、模板 CAS 和跨年查询边界检查。时间与汇率接口使用测试替身，文件读写使用内存 Vault；测试不联网、不读取个人账本。

`npm run check` 再核对源码和已构建 `main.js` 完全一致、样式与安装文件一致、manifest / package 版本一致、移动端声明有效，并通过 Obsidian 接口替身加载全部打包模块。改动源码、指南正文或配图后必须重新构建再检查；检查成功后才安装或打包。接口替身检查不能替代 Obsidian 真机测试。

### 指南和离线图片

[图文使用指南](../INTRODUCTION.md) 是唯一的指南内容源。构建脚本自动收集 `src/*.js`，并将指南正文和它引用的本地 PNG / JPEG / WebP 等图片编入虚拟模块 `./guide-content`，随 `main.js` 一起发布。`src/guide-content.js` 不需要存在，也不要手工维护第二份指南。

应用内通过面板底部、个性化设置或「打开使用指南」命令进入。`guide.js` 使用 Obsidian MarkdownRenderer 展示正文，图片来自已打包的数据，不依赖源码目录、外网或用户库中的说明文档。GitHub 中相同 Markdown 仍使用相对图片路径。指南中的外部帮助链接需联网访问；用户账户、真实金额与凭据不得出现在示例或截图中。

运行时只使用 Obsidian 与浏览器 API，不依赖 Node.js、Electron 或桌面文件路径。`src/mobile.js` 在触摸设备上处理 VisualViewport、弹窗高度和焦点可见区域；关闭弹窗时释放监听。`src/identity.js` 在缺少 `crypto.randomUUID` 时使用 `getRandomValues` 生成 UUID v4，不改变已有记录 ID。

顶部操作按主要记账入口与随手工具分组。`icons.js` 用固定 SVG 几何绘制图标，`decorate()` 只装饰现有按钮，不替换事件和错误处理。纯图标按钮保留完整 `aria-label` / `title`，触摸界面显示短标签；响应式布局同时使用容器查询以适配 Obsidian 窄分屏。图标与样式不产生额外账目字段，不加载在线资源。视图刷新保留搜索、类别选择、展开与滚动位置；不增加未保存表单拦截或自动草稿功能。

## 读取、写入与恢复边界

`storage.js` 只扫描当前设置的数据目录，按文件路径、对象和修改状态缓存解析结果；面板一次扫描共享读取快照。未变化的文件不重复解析，保存与 Vault 事件使相关缓存失效，切换目录清空旧目录缓存。手动刷新及生成月报会重新核验来源，默认直接读写校验路径仍读取新内容。缓存不写成另一本账本。

存储队列在操作进入时捕获数据目录，真正写入前再次核对；文件快照、行内容或目标月份不符合预期时停止覆盖。跨文件移动先写目标再移除来源，失败时比较内容并尝试回滚，避免覆盖外部同步改动。不要将缓存结果当作写入依据，也不要绕过共享队列直接修改账目。

`recovery-store.js` 的 `listRecovery()` / `restoreRecovery()` 按源文件快照、行位置及内容指纹区分历史版本。恢复保留 ID、精确金额、原币与备注；已有同 ID 有效记录、原专项归档或预览已过期时拒绝恢复。`listDuplicates()` / `resolveDuplicate()` 让用户明确选择保留版本，其余支持处理的流水先归入回收站，不自动合并金额。重复专项元数据、旧单笔或损坏格式只提示检查。多文件处理沿用快照校验与失败回退。

参考汇率缓存使用 `fetchedAt` 与本地日期 `checkedOn` 标识获取时间。前一可用日的临时汇率在跨日后重新查询，历史日期七天观察期内每日最多一次，之后允许服务提供的周末 / 假期参考日稳定缓存；取得所请求日期的历史汇率则可直接稳定缓存。旧缓存缺少核验日期时重新查询。此规则只影响参考缓存，不能改写已存入 Markdown 的交易汇率快照。缺少汇率的相关合计展示「待补全」，不要把已知部分显示成总额。

## 年份目录与兼容迁移

凭证使用 Vault `createBinary/readBinary/getResourcePath`，浏览器 File 在表单确认前仅保留在内存。成功保存交易后立即消费导入令牌，再处理分类偏好或刷新；失败回滚只接受本次令牌，复核文件对象、字节、修改状态及所有笔记引用后才清理。取消或切换目录发生于异步导入期间，也必须走同样规则。移除原有附件关联不删除文件；Markdown 表追加凭证列时保留原列与正文，凭证路径参与指纹比较。

模板笔记由金融扫描显式忽略。模板字段必须使用白名单；应用模板只操作当前表单，不调用保存账目，也不保存 FX 快照、日期、ID 或附件。空金额保留为待填，不转换成零元账目。模板新建、编辑、删除均通过 FinanceStore 队列和内容比较，校验当前目录及同范围名称唯一性。

跨月查询使用当前日历日期的范围预设，先筛选再准备所需汇率，默认只查日常。筛选、金额和列表共享同一匹配集合；支出筛选不将未查询退款解释为零退款净额。查询视图加入统一刷新队列，保留焦点、筛选与浏览位置，不生成额外账本。

专项在 `专项/名称.md` 中跨年保存，不按月拆分。新建和编辑在共享写入队列中检查名称唯一性（含归档、NFKC 规范化与大小写折叠）及目标路径冲突。内部 ID 永久保留，固定支出归属继续按 ID 关联。旧版自动生成的编号文件通过 `FileManager.renameFile` 整理，正文不重写，链接按 Obsidian 的库设置处理；重名、重复 ID、路径占用和格式问题均保留文件并提示。编辑时重命名失败会尝试仅回滚本次元数据，保留其他位置的并发修改；不能安全回滚时报告部分完成，供用户检查。手动选择的其他路径不会自动改名。

存储扫描分别返回 `records`（日常与理财）、`projectRecords` 与 `projects`，所有有效交易全局校验重复 ID。日常汇总、分类图与搜索也明确排除专项字段；月报只读取日常记录。

专项外观由 `project-appearance.js` 的图标与配色白名单定义，`project-cover.js` 负责本地 SVG、封面、卡片和实时预览。`cover_icon` / `cover_color` 保存在专项属性中，内部对象使用 `coverIcon` / `coverColor`。缺省或无效的外观值安全降级，不影响财务数据解析；读取旧笔记不补写字段。外观包含在设置签名中，沿用共享队列和冲突保护，分类追加、改名及回收站操作保留外观。外观只使用本地矢量与 CSS，无远程图片和额外资源文件。

固定清单兼容原八列与带币种的九列。首次保存专项归属时升级为十列，在币种之后追加「所属专项ID」；空值表示日常。付款期次 ID 在日常与专项之间统一查重，调整计划归属不重写旧付款。更改周期时也会检查已存在的专项付款，避免重复生成期次。

`projectsEnabled` 是独立显示偏好，缺省开启；隐藏入口不会删除专项或改变固定付款归属。`incomeEnabled` 与 `investmentEnabled` 不限制专项的支出和退款。跨账本迁移由存储写队列串行处理，校验每个文件快照，目标写入后再移除源行；失败回退采用内容比较，保护同步期间的外部修改。迁移 UI 在确认前显示笔数、支出、退款与净额，并在移动完成后单独更新已有月报，避免月报错误触发重复迁移。

流水统一写入 `流水/YYYY/YYYY-MM.md`，月报统一写入 `月报/YYYY/YYYY-MM.md`。`src/periods.js` 集中维护路径规则，面板的「打开本月流水」和阅读视图识别共用这套规则。跨年编辑会将记录移入目标年份的月笔记；固定支出付款按实际付款日期归档。

读取或写入月份笔记时，存储层会将旧的 `流水/YYYY-MM.md` 与 `月报/YYYY-MM.md` 移入对应年份目录。迁移使用 Obsidian `FileManager.renameFile`，保留正文、属性、手写复盘，并按 Obsidian 的链接更新设置处理引用；不会复制出第二份流水。请在 Obsidian 提示时允许更新本次相关链接。

新旧路径同时存在、月份属性不符、无效流水行、目标路径被占用或迁移中笔记发生变化时，不覆盖文件；面板提示问题，待核对后重试。重复迁移不会重复创建笔记。同步到另一设备后，读取到的旧平铺月份文件也会沿用同样规则处理。

## 安装与打包

先完成上述构建与检查，再安装当前三个发行文件。PowerShell 安装脚本**必须显式指定目标库**，没有个人路径默认值：

```powershell
./scripts/install.ps1 -VaultPath '你的 Obsidian 库路径'
```

脚本先检查目标库的 `.obsidian` 和三个安装文件是否齐全、manifest ID 是否正确，再进行复制。仅替换 `main.js`、`manifest.json`、`styles.css`，保留个人 `data.json` 和流水数据。可选 `-Enable` 会把插件加入启用列表；需要修改已有启用列表时，脚本会先在 `.local/backups/` 保留该列表的副本。执行前应核对目标库，复制后在 Obsidian 中重新加载插件。

打包示例：

```powershell
Compress-Archive -LiteralPath './安装文件/local-finance-notes' -DestinationPath './MyPocket-1.0.0.zip' -Force
```

发布时保持 `manifest.json` 与 `package.json` 的版本一致，检查包内只有 `local-finance-notes/` 下的三个安装文件。不要把账本、个人 `data.json`、临时文件、备份或云服务凭据加入安装包。

GitHub 可公开源码、README、INTRODUCTION、说明文档图片、许可证和发布包。`流水数据` 属于用户个人资料，不应发布。多设备配置说明集中在[使用指南：电脑与手机同步](../INTRODUCTION.md#7-电脑与手机同步)，不要在开发文档中复制账号或远程服务密钥。

## 手机验证范围

手机布局已通过浏览器中的安卓触摸模拟，覆盖窄屏、横屏、平板、键盘高度变化、记账表单、分类、计算器、备忘录和筛选图表。真实安卓软键盘、WebView、Obsidian 原生弹窗样式、文件权限和 Remotely Save 仍需用手机确认。iOS 没有经过 WebKit 或真机验证。

人工验收时可使用独立笔记库，检查金额保存、分类选择、横竖屏切换、备忘录后台保存，以及同步到电脑后的流水统计。
